# Завдання 3. Порівняння алгоритмів сортування

## Опис

У цьому завданні порівнюються три алгоритми сортування:

- **Insertion sort** - сортування вставками.
- **Merge sort** - сортування злиттям.
- **Timsort** - вбудований алгоритм Python, який використовується у `sorted()` та `list.sort()`.

Мета експерименту - емпірично перевірити, як алгоритми поводяться на різних наборах даних, і показати, чому на практиці зазвичай використовують вбудовані алгоритми Python.

## Як запустити

```bash
python Task_3/main.py
```

Або з папки `Task_3`:

```bash
python main.py
```

## Як працює програма

Файл `main.py` містить власні реалізації `insertion_sort` і `merge_sort`, а також функцію `timsort`, яка викликає вбудовану функцію `sorted()`.

### Insertion sort

Функція `insertion_sort(data)` копіює вхідний список і поступово вставляє кожен елемент у правильну позицію серед уже відсортованих елементів.

Цей алгоритм простий і може бути швидким на малих або майже відсортованих масивах, але на великих випадкових або зворотно відсортованих даних працює повільно.

Теоретична складність:

- найкращий випадок: `O(n)`;
- середній випадок: `O(n^2)`;
- найгірший випадок: `O(n^2)`.

### Merge sort

Функція `merge_sort(data)` рекурсивно ділить список навпіл, сортує кожну половину окремо, а потім об'єднує їх за допомогою функції `merge(left, right)`.

Цей алгоритм працює значно стабільніше на великих наборах даних, ніж сортування вставками.

Теоретична складність:

- найкращий випадок: `O(n log n)`;
- середній випадок: `O(n log n)`;
- найгірший випадок: `O(n log n)`.

### Timsort

Функція `timsort(data)` використовує `sorted(data)`. У Python ця функція реалізована на основі Timsort.

Timsort є гібридним алгоритмом: він поєднує ідеї сортування злиттям і сортування вставками. Завдяки цьому він дуже ефективний на реальних даних, особливо якщо дані вже частково впорядковані.

Теоретична складність:

- найкращий випадок: `O(n)`;
- середній випадок: `O(n log n)`;
- найгірший випадок: `O(n log n)`.

## Тестові дані

Програма перевіряє алгоритми на масивах розміром `100`, `1000` і `5000` елементів.

Для кожного розміру генеруються такі набори:

- `random` - випадкові числа;
- `sorted` - вже відсортований список;
- `reversed` - список у зворотному порядку;
- `nearly sorted` - майже відсортований список із невеликою кількістю перестановок.

Для заміру часу використовується модуль `timeit`. Кожен тест повторюється кілька разів, а в результат береться найкращий час.

## Аналіз результатів

На малих масивах різниця між алгоритмами не дуже велика, але Timsort все одно залишається найшвидшим.

На масивах із `1000` і `5000` елементів добре видно різницю між `O(n^2)` і `O(n log n)`. Сортування вставками різко сповільнюється на випадкових і зворотно відсортованих даних. Наприклад, для `5000` зворотно відсортованих елементів `Insertion sort` виконався за `0.468318 сек.`, тоді як `Merge sort` - за `0.003761 сек.`, а `Timsort` - за `0.000017 сек.`.

Merge sort працює значно стабільніше, бо його складність залишається `O(n log n)` незалежно від початкового порядку елементів.

Timsort показує найкращі результати, особливо на вже відсортованих і майже відсортованих наборах. Це пояснюється тим, що він оптимізований для реальних даних, у яких часто вже є частково впорядковані фрагменти.

## Висновки

Емпіричні результати підтверджують теоретичні оцінки складності:

- `Insertion sort` підходить для малих або майже відсортованих списків, але є неефективним для великих масивів.
- `Merge sort` значно краще масштабується і стабільно працює на великих наборах даних.
- `Timsort` є найефективнішим у більшості випадків, бо поєднує переваги сортування злиттям і сортування вставками.
